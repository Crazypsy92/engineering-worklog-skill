# Engineering Worklog & Daily Review Skills｜研发报工与每日复盘

本仓库包含两个独立的 AI Skills：engineering-worklog 负责企业早晚报工，daily-review 负责全天工作、学习、个人生活与杂项的整理复盘。均以中文输出，适用于支持 SKILL.md 的助手。

## 两个 Skill 的定位

| Skill | 什么时候用 | 输出侧重点 |
| --- | --- | --- |
| engineering-worklog（根目录 SKILL.md） | 早间开工、晚间开工、结束报工、加班报工 | 任务定义、定性目标、数量、工时、输出物、逐项完成比例 |
| daily-review（skills/daily-review/SKILL.md） | 一天结束、整理聊天与日志、Obsidian 日记、个人复盘 | 今日事宜、工作与学习、生活、问题与处理、实际结果、后续、个人思考 |

企业报工不自动包含私人事项；全天复盘不强制套用8H或逐条完成100%。必须区分“提出任务/讨论方案”“实际执行完成”和“测试验收通过”。

## 固定报工口令

| 口令 | 对应操作 |
|---|---|
| 白天开启报工 | 白班开工，填写六个计划字段 |
| 白天结束报工 | 白班结束，填写对应完成结果 |
| 晚上开启报工 | 加班开工，新建独立计划 |
| 晚上结束报工 | 加班结束，填写对应完成结果 |

口令优先于当前时间。“白天结束报工”表示结束白天开启的白班，不受实际填写时间限制。四个口令无需再次确认报工阶段。

## 研发报工工作流

**白班与晚间加班分开报工，每个班次都独立执行开工→结束。**

- 不加班：白班开工 → 白班结束（2次）。
- 有加班：白班开工 → 白班结束 → 晚间加班开工 → 晚间加班结束（4次）。
- 白班结束后说“晚上报工”，默认开启新的加班记录；加班结束只对应加班计划。
- 每个班次分别统计任务、工时、数量和输出物。白班8H、加班2H、当天10H是三个不同口径（仅示例）。
- 截图中已填写的字段直接继承，不擅自修改。

| 模式 | 触发说法 | 输出字段 |
| --- | --- | --- |
| 开工计划 | 早上计划、准备做、开工、开启报工、今晚开工、晚上开启报工 | 六字段：任务详情、计划目标、计划数量、单位、计划工时H、计划输出物 |
| 结束报工 | 做完了、下班、收工、结束报工、完成情况、晚间完成结果 | 四字段：完成结果、实际数量、实际工时H、实际输出物 |
| 完整日报 | 早晚一起整理 | 每个实际班次分别填写开工与结束字段，未知信息保留待确认 |
| 加班报工 | 加班开工或加班结束 | 另建独立记录，开工六字段、结束四个核心字段；不自动设为8H |
| 一行版 | 用户明确要求一句话、精简版 | 按用户指定阶段压缩 |

如果白班已经结束且加班尚未开工，直接按加班开工处理。只有班次和阶段确实无法判断时才简短确认。

## 核心写作原则

- **严格对应原计划：** 用户截图、早间计划和明确任务是首要依据。不得擅自替换项目或任务。
- **避免重复报工：** 补报历史工作时，先检查当天已报项目；已报内容不重复。无法确认时先问一句。
- **简洁易懂：** 这是企业报工表，不是技术报告。每项优先一句话，删除背景铺垫、长篇原理和不必要的内部术语。
- **简洁但要量化：** 保留测试组数、次数、执行步数、成功/失败数、误差、交付数量等1～3个关键指标；没有证据的数字不编造。
- **工作量与测试结果分开：** 完成测试不代表测试通过；执行进度100%不代表任务成功率100%。
- **完成结果逐项标注：** 每一条末尾都使用“已完成XX%”，例如“1. 完成3类测试共12次，10次通过、2次发现异常，测试工作已执行完毕，已完成100%。”
- **数量口径一致：** 计划数量和实际数量按工作包统计，不把测试次数、仿真步数和报告份数相加。
- **工时真实：** 普通白班计划工时默认8H；晚间/加班计划不自动套用8H；实际工时未知时写“待确认”。
- **只列真实产物：** 不虚构报告、文件、PR、提交、路径或验收结果。

## 表单字段

### 开工计划（早上或晚上均可）

1. 任务详情（定义）：今天具体做什么，建议2～3项，每项写清对象、动作和数量/范围。
2. 计划目标（定性）：一句话说明做到什么程度算完成。
3. 计划数量（定量）：按工作包数量填写。
4. 单位：默认“项”，也可按公司规定使用“组/次/份”。
5. 计划工时H：普通白班默认8；晚间/加班按实际计划填写，未知为待确认。
6. 计划输出物：写预计留下的测试记录、数据、报告或问题清单。

### 结束报工（对应同一班次）

1. 完成结果：逐项对应原计划，写明实际动作、关键指标和结果，每条末尾标注“已完成XX%”。
2. 实际数量（定量）：沿用计划数量的统计口径。
3. 实际工时H：只填用户确认或可靠记录支持的时长。
4. 实际输出物：只列真实生成或留存的产物。

表单辅助字段：是否执行（按实际情况）、单位（沿用该班次计划）、工作自评（沿用用户确认值）、备注（无则留空）。已有工序和关联项目保持不变。

## 安装（Codex）

用户级安装（WSL/Linux）：

    mkdir -p ~/.agents/skills
    git clone https://github.com/Crazypsy92/engineering-worklog-skill.git ~/.agents/skills/engineering-worklog

项目级安装：

    mkdir -p .agents/skills
    git clone https://github.com/Crazypsy92/engineering-worklog-skill.git .agents/skills/engineering-worklog

    ln -s "$HOME/.agents/skills/engineering-worklog/skills/daily-review" "$HOME/.agents/skills/daily-review"

## 触发示例

晚间开工计划：

    使用 engineering-worklog 帮我写今晚的开工报工。
    今晚计划做两组仿真测试，检查抓取、抬升和放置三个环节，整理一份结果记录。
    按六个计划字段输出，简短但保留量化指标。

白班结束报工：

    使用 engineering-worklog 帮我写白班结束报工，按早上的三项计划逐项对应。
    每条完成结果都按“1. XXXXX，已完成100%。”格式填写。
    只输出四个结束字段。

加班结束报工：

    使用 engineering-worklog 帮我写今晚加班结束报工，只对应今晚的开工计划。
    保留量化结果，逐项标注已完成百分比。

补报历史工作：

    使用 engineering-worklog 帮我补报昨天尚未填写的工作。
    先核对哪些项目已经报过，只整理未报内容，不要重复。

## 每日复盘

使用 daily-review，总结指定日期的全部聊天和原始记录。分别整理工作研发、论文和技术学习、个人阅读/软件体验、问题与处理、未完成与明日重点。

日志文件名固定采用 YYYY-MM-DD.md（例如 2026-11-12.md），文件头保留 type: daily-log、date、tags: daily-log 属性，之后是 # YYYY/MM/DD 星期X 日期标题和模板说明引用段。个人工程事项只列在今日事宜和个人对话中，不得写进工作研发记录。今日事宜置顶，日终回顾在关联资料前。

**隐私约束：** 本仓库是 Public；只发布通用指令、空白模板和匿名虚构示例。真实个人日记、工作数据、照片、公司资料不自动上传 GitHub。
